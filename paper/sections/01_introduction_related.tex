\section{引言}
\label{sec:introduction}
% =========================================================

储能电站运维知识天然具有动态性与过程性。一次异常处置往往需要同时参考设备状态、告警与巡检记录、历史工单、操作规程以及处置后的验证结果。与静态知识问答不同，系统不仅要判断“哪些证据与查询相关”，还要回答两个更严格的问题：这些证据在查询时刻是否已经可知，以及它们能否共同形成支持当前决策的完整证据过程。

检索增强生成（RAG）通过外部检索补充语言模型的参数知识，是当前知识密集型生成的重要范式~\cite{lewis2020rag}。在检索侧，BM25 仍是强词法基线，而 DPR、ColBERT 等神经检索方法通过稠密表示或 late interaction 改善语义匹配~\cite{karpukhin2020dpr,khattab2020colbert}；BEIR 进一步表明，不同检索范式在跨域泛化上具有明显差异~\cite{thakur2021beir}。在生成侧，FiD 说明多段检索证据可以被生成模型有效聚合~\cite{izacard2021fid}，Self-RAG 则进一步研究了检索、生成与自我反思的联合控制~\cite{asai2024selfrag}。

然而，普通 RAG 通常把候选文档视为彼此独立的相关性单元。对于持续更新的运维记录，这一假设并不充分。首先，运维证据具有双时间属性：事件发生时间与记录进入系统的可用时间并不总是一致，晚到记录不能被历史查询提前使用。其次，维护决策通常依赖互补证据：状态观察支持检查，检查结果支持诊断，诊断引出处置，而处置后的复测又验证前序判断。单条文档得分较高并不意味着 Top-$k$ 集合能够覆盖完整过程。

近期工作开始从不同角度缓解这些问题。时间感知 RAG 显式建模时间约束或跨时间区间的信息变化~\cite{zhang2025mrag,lau2025tarag}；多跳检索通过逐步条件化寻找互补证据~\cite{xiong2021mdr,trivedi2023ircot}；RAPTOR、GraphRAG 与 HippoRAG 则通过层次结构、图结构或图上的传播机制增强跨文档知识组织~\cite{sarthi2024raptor,edge2024graphrag,gutierrez2024hipporag}。这些研究共同说明：复杂知识任务的关键不只是“找到相关文本”，还在于如何组织和选择多个相互依赖的证据。

本文提出 TEF-RAG（Temporal Evidence Flow Retrieval-Augmented Generation）。其核心思想是：在查询时刻可见的候选证据之间建立查询条件化的有向语义关系，并将检索目标从独立节点排序改写为证据集合排序。系统首先通过确定性的资产、时间和规程约束排除不可使用的记录；随后学习哪些候选证据对值得进行关系判断，并构建时序证据图；最后对固定大小的候选集合进行非线性 pairwise ranking，使模型直接学习“哪个证据集合更完整、更适合作为当前查询的上下文”。

TEF-RAG 与一般图检索的区别在于，图并非由静态实体关系预先定义，而是在查询条件下由当前可见的运维证据动态形成；与时间感知排序的区别在于，时间约束只是合法性边界，最终目标仍是恢复角色互补且关系一致的证据集合；与逐跳多跳检索的区别在于，目标结构允许分支、更新、替代和不确定性保留，而不要求是一条单一线性路径。

在本文的具身运维场景中，检索并不是终点。选出的 evidence flow 被送入统一生成器，形成标准化工单与带依赖关系的动作计划，为后续 planner、约束检查和机器人执行提供证据化接口。本文聚焦这一链条中的 evidence retrieval 与 structured planning context，不把真实机器人闭环控制或现场安全认证作为已完成贡献。

本文的贡献可概括为三点：
\begin{enumerate}
    \item 提出面向动态运维知识的 Temporal Evidence Flow 检索问题，将时间可见性与证据集合完整性统一到同一检索框架中；
    \item 提出“学习式证据对提议 + 查询条件化关系图 + 非线性集合排序”的方法，使检索目标由独立文档相关性转向集合级流程效用；
    \item 构建受控时序运维 benchmark，并通过检索指标与统一生成器下的结构化生成指标，验证 evidence-flow 质量能否向下游工单与动作计划传递。
\end{enumerate}

\subsection{相关工作}
\label{sec:related_work}
% =========================================================

\textbf{检索增强生成与神经检索。}
经典 RAG 将外部检索器与生成模型结合~\cite{lewis2020rag}；DPR 与 ColBERT 分别代表稠密双塔检索与 late-interaction 检索~\cite{karpukhin2020dpr,khattab2020colbert}。FiD 从生成侧展示了多证据聚合能力~\cite{izacard2021fid}，BEIR 则系统比较了稀疏、稠密、重排等多种检索范式的泛化能力~\cite{thakur2021beir}。这些方法主要优化独立文档相关性，而本文关注集合中证据之间的时序与语义依赖。

\textbf{时间感知与多跳检索。}
MRAG 与 TA-RAG 将时间条件显式引入检索~\cite{zhang2025mrag,lau2025tarag}；MDR 与 IRCoT 通过逐跳或检索--推理交替来寻找多段证据~\cite{xiong2021mdr,trivedi2023ircot}。TEF-RAG 同样强调互补证据，但进一步区分事件时间与可用时间，并允许证据结构包含更新、替代、验证和不确定性传播。

\textbf{结构化与图式 RAG。}
RAPTOR、GraphRAG 与 HippoRAG 表明，层次或图结构能够改善跨文档信息整合~\cite{sarthi2024raptor,edge2024graphrag,gutierrez2024hipporag}。不同于这些通常从文档层级或实体关系构图的方法，TEF-RAG 的边由当前查询和当前可见运维记录共同决定，其语义直接对应运维证据之间的支持、更新、限定与验证关系。

\textbf{具身运维与电池智能决策。}
RAG 也开始被用于机器人现场任务与专业设备操作。SayComply 研究了面向现场机器人的操作合规知识检索，RAGLRO 则将检索增强语言模型用于机器人操作任务~\cite{ginting2025saycomply,wang2026raglro}。在电池领域，LiBrain 与 TimeSeries2Report 分别探索时序信息、检索知识与语言模型在电池诊断和管理中的结合~\cite{li2026librain,yang2026timeseries2report}。这些工作说明，从动态设备信息到可执行任务之间需要可靠的知识接口；本文进一步聚焦这一接口之前的证据选择问题，使后续工单与动作计划建立在查询时刻可见且流程完整的证据集合上。

\textbf{学习排序。}
TEF-RAG 的最终选择属于 query-level learning-to-rank。RankNet 以成对偏好学习相对排序函数~\cite{burges2005ranknet}；ANCE 等工作则说明难负样本对于学习有效检索边界十分关键~\cite{xiong2021ance}。本文将这一思想用于“证据集合”而非单条文档：训练目标直接比较同一查询下完整集合与高分但不完整的困难集合。
