\section{TEF-RAG 方法}
\label{sec:method}
% =========================================================

图~\ref{fig:tef_overview} 给出 TEF-RAG 的整体流程。方法由四个相互衔接的阶段组成：合法候选检索、学习式证据对提议、查询条件化关系建图，以及非线性集合排序。前两步控制候选规模，关系图负责表示证据之间的过程结构，最终排序器直接比较候选证据集合的整体效用。

\begin{figure*}[t]
    \centering
    \includegraphics[width=0.96\textwidth]{figures/tef_rag_overview.png}
    \caption{TEF-RAG 总体框架。系统先在查询时刻合法的候选证据上筛选关系候选对，随后构建查询条件化的 Temporal Evidence Flow，并在候选集合空间中利用非线性 pairwise ranking 选择至多五条证据作为 evidence flow；该证据集合再作为统一下游生成器的受控上下文。}
    \label{fig:tef_overview}
\end{figure*}

\subsection{候选证据准备与时序合法性}

TEF-RAG 首先对原始异构记录执行统一的合法性检查。资产不一致、事件发生在查询之后、记录在查询之后才可用，以及不适用于当前型号或时段的规程都会被直接排除。这一步不学习“相关性”，而是建立不可被后续模型突破的知识边界。

在合法集合 $\Candidates_q$ 上，BM25 产生宽候选池；随后根据词法相关性、时间新近性和查询角色兼容性等部署时可计算特征形成 Top-30 搜索池。该搜索池的作用是保持召回，而不是直接决定最终输出。当合法候选不足五条时，系统保留短输出，不进行人为填充。

\subsection{学习式 Pair Proposal}

若对搜索池中全部有序证据对进行语义关系判断，成本会随候选数平方增长。TEF-RAG 因此先学习一个轻量 pair proposer，对每个时间顺序合法的证据对 $(e_i,e_j)$ 估计其值得进入关系判断的概率：
\begin{equation}
p_{ij}
=
\sigma\!\left(
\mathbf{w}^{\top}\phi_p(q,e_i,e_j)+b
\right).
\label{eq:pair_proposal}
\end{equation}

$\phi_p(q,e_i,e_j)$
表示查询 $q$ 与证据对 $(e_i,e_j)$ 的特征表示，其中包括查询与两条证据的文本相关性、
两条证据之间的相似性、事件类型、时间间隔以及版本替代等信息。
若一对证据构成训练数据中已标注参考证据流的一条必要关系，则作为正样本；
其余时间顺序合法的证据对作为负样本。随后利用 logistic regression 
学习每个候选证据对的优先级，并仅将得分较高的证据对交给后续关系判断模块。

因此，pair proposal 的主要作用是以固定预算把后续语义关系推理集中在更有希望的证据对上，同时保持时间方向这一确定性约束。

\subsection{查询条件化的 Temporal Evidence Flow}

对保留的候选 pair，TEF-RAG 使用查询条件化的 LLM 关系判断器读取查询信息以及两端证据的
文本和元数据，并输出
\begin{equation}
h_{\eta}(q,e_i,e_j)
\rightarrow
(r_{ij},c_{ij}),
\end{equation}
其中 $r_{ij}\in\Rels$，$c_{ij}\in[0,1]$ 为关系置信度。只有预测为有效关系且达到置信度阈值的 pair 才进入图中。
若不存在足够明确的语义关系，则该证据对被丢弃，不加入证据图。关系判断器使用的固定提示词见附录~\ref{app:relation_prompt}。
将候选证据视为图中的节点，并将两条证据之间识别出的语义关系表示为有向边。
对于查询 $q$，Temporal Evidence Flow 图记为
\begin{equation}
\FlowGraph_q=(V_q,E_q),
\end{equation}
其中 $V_q$ 为候选证据集合，$E_q$ 为证据关系集合。
每条关系边可以写成 $(e_i,r,e_j)$，表示证据 $e_i$ 通过关系 $r$ 指向证据 $e_j$，其中 $r\in\Rels$。

关系词汇表覆盖 supports、governs、qualifies、contrasts、prerequisite、preserves uncertainty、resolves、supersession、updates 与 verifies 等过程关系。边方向遵循事件时间或明确的前置/更新方向，因此图可以形成分支和汇合，而不强制退化为单一路径。

与静态知识图不同，$\FlowGraph_q$ 是查询条件化的：同一对记录在不同查询下可能具有不同的任务作用。关系判断器也不能突破第~\ref{sec:problem} 节定义的合法性边界，因此晚到证据、未来事件或不适用规程不会因语义模型的判断而重新进入候选集。

\subsection{候选证据集合构造}
关系图建立后，TEF-RAG 需要进一步比较不同的证据组合，而不是继续独立地对单条证据进行排序。
由于直接枚举整个搜索池中的所有五元组合开销较大，我们只构造一批具有较高潜力的候选集合。

具体而言，首先从节点分数最高的证据中枚举五元组合，以覆盖高相关证据之间的不同搭配；
同时保留前序搜索得到的高质量集合，并在这些集合附近进行单条证据替换，
使排名稍低但能够补充关键任务角色的证据仍有机会进入候选集合。

对每个集合 $\Selected$ 提取集合级特征 $\phi_s(q,\Selected,\FlowGraph_q)$。最终模型使用 62 个特征，涵盖：
\begin{itemize}
    \item 节点相关性、时间分数和角色兼容性的统计量；
    \item 事件类型与来源类型的覆盖度；
    \item 集合内部有效边数量、边置信度、连通分量和最长有向路径；
    \item 时间跨度、平均事件间隔以及来源/文本多样性；
    \item 冗余、缺失角色与孤立节点等惩罚信号。
\end{itemize}
这些特征共同描述“所选证据作为一个整体是否形成了完整任务支持结构”，而不是简单重复单节点得分。

\subsection{非线性 Pairwise Set Ranking}

最终排序器采用小型非线性 RankNet~\cite{burges2005ranknet}。令
\begin{equation}
s_{\theta}(q,\Selected)
=
\operatorname{MLP}_{\theta}
\!\left(
\phi_s(q,\Selected,\FlowGraph_q)
\right),
\end{equation}
最终阶段采用基于成对偏好的集合排序。
对于同一个查询，候选库中通常存在多个完整证据集合和多个不完整证据集合。
我们从中构造若干训练对
$(\Selected_i^+,\Selected_j^-)$，
其中 $\Selected_i^+$ 表示能够形成完整参考证据流的候选集合，
$\Selected_j^-$ 表示缺少关键证据或关系不完整的候选集合。

对于每一个训练对，排序器希望完整集合获得更高分，其损失定义为
\begin{equation}
\ell(q,\Selected_i^+,\Selected_j^-)
=
-\log \sigma\left(
s_{\theta}(q,\Selected_i^+)
-
s_{\theta}(q,\Selected_j^-)
\right).
\label{eq:ranknet_pair_loss}
\end{equation}

所有训练对的损失取平均，得到最终训练目标：
\begin{equation}
\mathcal{L}
=
\frac{1}{|\mathcal{P}|}
\sum_{(q,\Selected_i^+,\Selected_j^-)\in\mathcal{P}}
\ell(q,\Selected_i^+,\Selected_j^-),
\label{eq:ranknet_loss}
\end{equation}
其中 $\mathcal{P}$ 表示训练过程中构造的全部候选集合对。

第一轮训练从负样本中选择规则式集合评分较高的候选。该评分综合考虑单条证据质量、集合内部关系、任务角色覆盖、内容冗余与孤立证据，完整定义见附录~\ref{app:hand_score}。
这类集合通常包含多条高相关证据，但仍缺失某些关键证据或关系，
因此比随机负样本更难区分。
同时保留少量具有不同组成的负样本，以增加训练样本的多样性。

完成第一轮训练后，我们使用当前排序器重新为所有负集合打分，
并选择其中模型评分最高的失败集合作为 hard negatives。
这些集合虽然已知不能形成完整的参考证据流，
却最容易被当前模型错误地排在前列。
随后利用这些困难负样本进行第二轮训练，
使排序器进一步学习区分正负样本。
\subsection{与具身运维生成器的接口}

TEF-RAG 的输出并不是机器人低层控制指令，而是面向后续具身执行的证据上下文。统一下游生成器根据查询和检索证据生成标准化工单及带依赖关系的动作计划；这些结构化输出可以进一步交由 planner、约束检查器和机器人执行器处理。

为隔离检索质量的影响，所有比较方法共享同一个下游生成器。生成器只接收查询与当前方法选出的证据记录，不接收方法名称、检索分数或 TEF 图结构。固定生成提示词见附录~\ref{app:generation_prompt}。本文评价到结构化工单与动作计划为止，不把真实机器人闭环执行或现场安全认证作为已解决问题。
