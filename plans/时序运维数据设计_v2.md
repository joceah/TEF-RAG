# 时序运维数据设计 v2：阶段1方案与小样审核

日期：2026-09-12。作者已认可总体计划的三点并授权阶段1。本文件及小样完成资料与案例设计；正式数据集、检索实验和生成实验尚未启动。

## 1. 已交付与真实依据

本阶段形成16条合成事件链、78条审阅记录、32个查询时点，另有10项已查看的核心资料及1项待核验数据入口。所有案例使用虚拟设备和自拟中文文本，不能称为真实现场记录。

详见[资料来源与适用边界](时序运维资料与案例设计_v1/资料来源与适用边界.md)和[16条案例全文](时序运维资料与案例设计_v1/事件链小样_16例.md)。来源表逐项记录出处、章节或页码、访问日期、支持的设计、不支持的结论和许可状态。

资料分工如下：厂家手册提供症状判别与检查对象；监管调查和运营方分阶段公告提供监测缺失、流程演变和知识更新的实例；研究数据记录提供设备层级；MaintIE提供维护短文本的结构参考。未取得代表性的日常故障频率，当前不声称拟合了真实长尾分布。没有下载或读取大规模测量文件。

## 2. 故障与时序任务覆盖

此表是设计覆盖矩阵，不能作为故障发生率统计。

| 案例 | 物理/业务背景 | 主时序任务 | 需要跨记录完成的判断 |
|---|---|---|---|
| C01 | 相似电压异常再次出现 | 恢复后新异常 | 上次异常、恢复证据与本次起点共同判断，根因相同仍未证实 |
| C02 | 持续低电压问题 | 行政关闭与重开 | 业务关闭不等于技术恢复，新编号不等于新故障 |
| C03 | 电压差的阶段变化 | 历史原因能否沿用 | 充电阶段与静置后偏离区分，不能只匹配症状词 |
| C04 | 维护阶段控制切换 | 非故障参照 | 用维护背景解释现象，不把停充直接当硬件故障 |
| C05 | 信号连接异常 | 检查晚到 | 发生在过去但未入库的结果不能提前使用 |
| C06 | 逆变器通风问题 | 作业完成与复测 | 相同测量对象还需可比工况，才能判断处理效果 |
| C07 | 传感器线路异常 | 证据补齐 | 前期只知读数异常，后期检查支持测量链解释 |
| C08 | 绝缘告警与降雨 | 相关性与因果 | 天气相邻不能代替定位检查 |
| C09 | 冷却连接异常 | 监测缺失与事后回顾 | 无告警不等于无异常，晚到本地记录改变可知范围 |
| C10 | 通风与通信并发事项 | 同设备多张工单 | 最新工单并非查询指向工单，不跨事项借用完成状态 |
| C11 | 资料核对规程 | 发布与生效分离 | 新版可见但未生效；生效后新增要求实际改变输出 |
| C12 | 不同配置的资料要求 | 型号和动作依赖 | 新版不适用目标配置；核对先于签署有明确依据 |
| C13 | 用户计划停用 | 非故障与背景晚到 | 控制原因可知、审批背景暂未知，允许部分回答 |
| C14 | 测量记录冲突 | 更正与证据可信度 | 最新意见未必正确，依仪器核验解释冲突 |
| C15 | 误挂设备附件 | 对象更正 | 关联元数据和原文冲突需核对，更正不改写早期知识 |
| C16 | 调查结论更新 | 认识演变 | 区分初步假设、检验与综合结论，保留历史版本 |

按设计者主观标记，有2条简单参照、3条单一困难、11条组合困难。这是为让作者检查机制而刻意选择的覆盖小样，**不是拟用于正式实验的难度比例**。阶段2需保留更多普通情形，不能复制当前比例或把低得分当设计目标。

物理背景覆盖电压、控制/连接、通风、传感器、绝缘、冷却和非故障运行；规程与记录冲突是额外业务难度，不冒充新的物理故障类别。未添加鸟巢、接触器故障等缺少本轮具体依据的场景以凑数量。

## 3. 记录、查询和评价标注的边界

每条审阅记录有业务内容、发生或形成时间、进入系统时间；所有自拟时间为UTC+8。规程另外在正文明确发布、生效及失效区间。案例中的真实来源只解释设计动机，不给出虚拟设备的最终诊断。

未来输入检索器的内容可包含原始记录、自然存在的工单号、设备对象、时间、版本与来源。评测专用信息必须分开：案例标题、难度、关联结论、参考答案、必要支持记录及禁止证据不能进入索引、摘要、图或提示。C01等文件顺序与案例编号也不应成为事件归属捷径。

当前 `设计卡_审阅专用.json` 将记录和答案放在同一审阅文件中，**只能用于作者审核与一致性检查，严禁直接作为检索库导入**。阶段2经审核后再输出明确分离的语料和评价文件；本轮没有构建SQLite、embedding或正式查询集。

查询要同时表达“问哪个时间的事件”和“允许看到哪个时间的资料”。大部分早期问题要求当时已知；后期回顾问题允许引用晚到记录，但必须说明这些信息此前不可见。

对错误或过期资料分角色处理：可以引用它来解释历史判断、版本差异或冲突；不能把它当作当前有效事实。C11/C12分别列出“可见但不能作为当前适用条款”的记录，不将它们与未来不可见证据混为一类。

## 4. 参考答案和生成任务如何设计

每个查询已有参考回答、必要支持记录、允许的替代表述与不可提前使用记录。此处的“必要支持”是待审候选，尚未冻结为唯一gold；作者可指出某条冗余、遗漏或有等价替代。

答案质量重点是：事件关系是否有恢复或连续性证据；故障说明是否超出检查结论；时间知识边界是否正确；相似症状是否找到判别依据；规程内容是否适用；未知项是否准确。不是每题都必须唯一诊断，也不是证据不足就拒绝回答全部内容。

C11/C12给出有具体内容差异和依赖的**合成试验资料核对规定**，仅支持资料核对计划。未提供真实厂家旧新SOP差异，也不能据它评价现场投运或带电作业安全。若论文后续要声称实体运维动作规划优势，需要另找可公开且适用的真实规程，明确其动作、条件和替代方案。

目前较多链通过“前期不足、后期补齐”观察生成变化，后续需加入答案不变但解释更新、长期无法确定、不同假设并存等情形，避免模型学到“晚一点就肯定能诊断”的新捷径。应设计可支持内容的标准，而非预设主方法答案。

## 5. 作者审核方式

建议先读C01、C02、C07、C10、C11、C15六条，分别覆盖恢复、行政状态、相似症状、并发工单、规程和更正，再审其余案例。每条按以下维度给出“通过/修改/删除”，不必讨论代码细节。

| 审核维度 | 具体问题 |
|---|---|
| 场景自然性 | 人是否会这样记录和询问？合成情节是否需要更贴近实际的依据？ |
| 技术合理性 | 观测只能支持疑似还是已确认？是否混用了电池与逆变器对象？ |
| 时间合理性 | 记录晚到是否明确，查询时间是否可理解？ |
| 证据充分性 | 当前全部可见文字是否已泄漏本应未知的结论？必要证据是否确实必要？ |
| 答案合理性 | 是否允许等价答案、部分回答与合理未知？是否对方法不公平？ |
| 生成可辨性 | 错选事件或规程究竟会让哪项内容变错，还是只改变引用编号？ |

建议反馈格式：“Cxx，r或q编号，通过/修改/删除，原因”。例如指出“C06-q1的负荷背景不够明确”，即可据此修订。作者审核身份如实记录，不能写作真人领域专家验证。

## 6. 阶段2的进入条件与后续边界

先按作者意见修订小样与必要支持，再确定数据数量、背景/挑战比例、故障配额和来源复用条件。基础观测与诊断结论分阶段生成；人员、设备、故障和模板不固定绑定；保留正常参照与不确定案例。

不原地修改现有数据v1，不使用旧validation/test调参。新数据划分要按设备和关联事件链隔离；同链改写、时间切片和近重复查询不能跨划分。阶段2只做新dev数据及质量审核，正式基线和生成实验另依阶段3预登记。

外部方法调查见[时序RAG外部对照调研](时序RAG外部对照调研_v1.md)：MRAG优先，Re³代码可用性待补查，Graphiti是时间图谱适配候选；尚未确认两套可运行完整系统，不提前承诺复现成功。
