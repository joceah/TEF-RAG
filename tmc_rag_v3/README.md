# TMC-v3 开发版本

`TMCRetrieverV3(records, assets, roles).retrieve(query, relevance)` 返回原记录ID、查询条件、候选数、来源用途与选择理由。`relevance` 由外部同一 Hybrid 检索器提供；`roles` 复用仅看单条公开记录的抽取。包不读取文件、标签或模型密钥。

- 查询显式工单号直接过滤，日期上下界采用左闭右开。
- 支持中文年月日、ISO日期、中文/数字月份及上中下旬；无年份时使用知识截止年份并输出假设。未实现任意相对时间、跨年省略推断或时间点级自然语言解析，不声称通用时间理解。
- 显式条件无可见命中返回空；复杂但未识别的时间表达不会伪造日期，保留语义检索候选，因此仍可能失配。
- 历史规程按有效期和所问期间交集选择，另标记是否当前适用。此标记并不能保证下游生成器不误用，尚需生成评价。
- `full` 以候选内归一化相关性为主，对明确请求的检查/恢复角色及多工单覆盖提供小幅奖励；最近时间只用于并列排序。
- `scoped_hybrid`、`scoped_latest` 共用相同查询条件，分别直接按相关性、时间排序。显式最新业务任务三种模式均执行业务倒序。

这是开发实现，不替换冻结的 `tmc_rag_v2`。新开发24题显示条件修复有效，但简单共享条件对照同样取齐证据，尚无完整选择的独立增益证明。既有98题验证没有重跑。
